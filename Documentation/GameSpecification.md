# SwordSlicer ゲーム仕様（実装解析版）

## 1. 操作

| 入力 | 実装上の動作 |
|---|---|
| 剣の近くで押下 | 剣がドラッグ状態でなく、投擲前の場合にドラッグ開始。剣の中心から強化後の攻撃範囲以内が押下可能領域。 |
| ドラッグ | `Camera.main.ScreenToWorldPoint` でワールド座標化し、剣操作エリアの矩形内にクランプして剣を追従させる。 |
| リリース | 直近のドラッグ差分を投擲方向にする。方向がほぼゼロの場合は上向き。ドラッグ時間に応じて速度を計算する。 |
| 「剣を取る」ボタン | ストックがあれば剣を生成。現在の剣が投擲済みなら次の剣を取得可能。 |

Input Actionは `Point`（Vector2）と `Press`。MouseとPointerの位置・押下バインディングがある。Touch専用の追加ジェスチャーやゲームパッド割当は確認できない。参照：[PlayerActions.inputactions](../Assets/InputActions/PlayerActions.inputactions)、[SwordControl.cs](../Assets/Scripts/Sword/SwordControl.cs)。

## 2. 戦闘ルール

- 剣は投擲後に操作できず、帰還もしない。投擲から5秒後に破棄される。
- 攻撃間隔は `max(minInterval, baseInterval - abs(rotateAmount) * 0.01)`。現行BattleSettingConfig assetの基準値は0.25秒、最小値は0.01秒。
- 敵の攻撃判定には `Physics2D.OverlapCircle` を1回使用し、返された単一Colliderから `EnemyHealth` を探す。範囲内すべての敵に一斉攻撃する仕様ではない。
- 検索結果に敵がいない場合は `SwordAttack` が攻撃状態を解除しないため、敵が範囲に入るまで毎フレーム検索が続く。敵がいないフレームでは通常の攻撃周期に戻らない。
- 敵側の `CheckAttackable` がfalseならミス表示後にその攻撃周期をリセットする。攻撃可能な敵には基礎ダメージを与える。
- 基礎攻撃力は `1 + 0.5 * 攻撃力レベル` に剣データの倍率を乗算。クリティカル率は `Clamp01(0.1 * レベル)`、クリティカル倍率は `1 + 0.2 * レベル`（現行コード・設定）。値は最大レベル等の実行時状態により変化する。
- 命中時にSE、カメラシェイク、攻撃エフェクトを生成し、ヒット数を更新する。ヒット数カウンターは剣Prefabの `SwordAttack` インスタンス単位で、結果にはその最大値が保存される。

## 3. 剣のストック・強化

- 最大ストックは5本、初期上限は1本。`1 + ストックレベル` を上限5でクランプ。
- 剣データはNormal / Advanced / Ultimateの3種。現行設定確率は0.6 / 0.3 / 0.1。
- 剣データはストック追加時に選ばれる。現行データでは鍛造基準間隔5秒にレベル倍率を適用する。
- 強化項目：攻撃力、投げる力、曲がる力、曲がる反応時間、攻撃範囲、クリティカル率、クリティカルダメージ倍率、鍛造間隔、ストック数。
- 投げる力・曲がる力・曲がる反応時間・攻撃範囲は解放レベルの範囲内でレベル調整可能。残りは購入時にレベルが上がる方式。
- 購入価格と倍率は `BattleSettingConfig.Upgrades.cs` のコード定義。`BattleSettingConfig.asset` に残る `priceEntries` は現行クラス側に対応するシリアライズ可能フィールドがなく、現在の価格設定の根拠として扱わない。

## 4. 敵・敵出現

敵は現行の `EnemySpawnScheduleSO.asset` に10エントリーあり、Prefab・敵別SOに参照されている。

| 敵 | 実装された挙動・条件 |
|---|---|
| スライム2種 | 基底移動による開始地点からターゲットへの線形移動。 |
| ゴブリン2種 | クールダウン後、ターゲット方向へ設定距離だけ移動。移動のたびにスプライトを反転する。 |
| ゾンビ | ダメージ後、残HPが直前基準の30%以下になると3秒無敵。無敵中は攻撃不可かつ移動停止。 |
| カエル | クールダウン後にターゲット方向へジャンプ。ジャンプアニメーション中は攻撃不可。 |
| トロール | Dataの正面方向からの攻撃を防ぎ、正面からの角度が閾値以上の側面／背面攻撃を許可。判定結果を0.5秒固定する。現行asset閾値は90度。 |
| ミノタウロス | ゴブリンと同じクールダウン・距離移動基底処理を利用し、個別のMinotaurDataSOを使う。 |
| キノコ | 非胞子個体は遅延後に1回繁殖し、現行assetでは3体を生成。胞子個体は埋まった状態から5秒後に移動可能となり、再繁殖しない。 |
| デビル | 定位置で10秒ごとに火の玉を3体生成する（現行asset）。 |
| 火の玉 | デビルから生成。設定した振幅・周期の正弦波でY方向に揺れながら移動。 |

すべての敵は出現位置・ターゲット・時間依存ステータス倍率で初期化される。敵が防衛ラインのY座標から0.1以内に入るとゲームオーバーイベントを発火する。

`EnemySpawnController`のフィールド初期値はテスト用経過時間300秒だが、現行`GameScene`では`testUnlockElapsedTime: 0`がシリアライズされているため、実際のScene開始値は0秒。

### 難易度と時間経過

難易度値はEasy / Normal / Hard / Extreme / Nightmare。現行の基礎ステータス倍率は順に0.8 / 1.0 / 1.2 / 1.5 / 2.0。難易度上昇間隔の係数は1.2 / 1.0 / 0.8 / 0.6 / 0.2。敵ステータスは `difficultyBase * 1.1^(elapsed / effectiveIncreaseInterval)`、スポーン間隔は `8 * 0.9^(elapsed / effectiveIncreaseInterval)` を使い、最短間隔は0.25秒。タイプ解放間隔は現行assetで20秒に難易度係数を掛け、最低5秒。報酬は敵の基本報酬に難易度基礎倍率を掛ける（時間経過による倍率は報酬式に使わない）。

**重要な実装制約**：スポーン抽選は `Random.value`（0～1）と各エントリーの累積重みを比較する一方、データ重みの合計が1を超える。最初の2エントリーの値だけで累積が1.6となるため、3番目以降は現状の式では選ばれない。敵の「解放」と「抽選対象になること」は別であり、確率分布の修正が必要。

## 5. ゲーム進行・結果・保存

- Scene順：`HomeScene` → `GameScene`（Build Settings上のindex 0, 1）。
- Easy等の選択は `EnemySpawnScheduleSO` のDifficultyLevelを変更して `GameScene` をロードする。
- 防衛ライン到達と撤退は同じGameOverイベント経路を使う。撤退が結果画面への遷移条件で、通常の勝利条件は確認できない。
- 結果画面：難易度、タイトル、防衛時間、敵撃破数、最大ヒット数、獲得通貨、剣生成数を表示。Unityroomへ総獲得通貨を送信し、Nightmareのみ防衛時間も送る。
- ホームから手動保存／ロード。保存対象は強化レベル、通貨、音量。`PlayerPrefs`にJSON形式で保存される。終了時自動保存、クラウドセーブ、セーブバージョン管理は確認できない。

## 6. UI

ホーム：ゲームモード、強化、保存／ロード、音量、遊び方。ゲーム中：剣ストック／生成進捗、剣の速度・回転・カーブ値、経過時間、通貨、撤退、音量。結果：上記結果指標とホーム／リトライ。

大半の画面はUI Toolkit（UXML/USS）で、浮遊ダメージ／クリティカル／通貨表示にはTextMesh Pro uGUIのPrefabを併用する。
